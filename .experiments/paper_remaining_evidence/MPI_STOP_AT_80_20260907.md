# MPI Full user stop at aligned epoch 80

The user explicitly shortened the running MPI Full experiment from120 to an
80-epoch effective comparison budget to align it with the80/60-epoch H36M
experiments. The process was already at completed epoch78 when this instruction
was applied. Stopping immediately would create an arbitrary78-epoch endpoint,
so the operational interpretation is: preserve training through complete
epoch80, verify `metrics.json` and latest raw/EMA checkpoint metadata are all at
epoch80, then terminate before epoch81 contributes a completed result.

The original config, optimizer, LR, EMA, data and weights are not modified or
restarted. Because the runtime config still declares120 epochs, a dedicated
identity-checked watcher sends SIGTERM only after complete epoch80 checkpoint
files exist. It then copies those immutable latest files to explicitly named
`raw_fixed_epoch80_user_stop.bin` and `ema_fixed_epoch80_user_stop.bin` and
records the user stop marker. A nonzero launcher exit caused by this deliberate
signal is `CANCELLED_USER_ALIGNED`, not a technical failure.

The amended primary result is minimum test-monitored EMA MPJPE within epochs
1-80, with same-checkpoint P-MPJPE/PCK/AUC; raw best within1-80 and the aligned
epoch80 raw/EMA endpoint are secondary. This is a mid-run user protocol change
and remains test-exposed. No MPI PoseMamba baseline will be launched.

W128 Detector training continues concurrently and is not signalled or changed.
